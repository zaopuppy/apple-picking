# 3D 地图编辑决策与实现记录

日期：2026-08-16  
状态：桌面版第一阶段已实现

## 结论

地图工坊采用“3D 主布局 + 2D 精确拓扑”的混合方案，不引入第三方编辑器作为地图真源。

- 建筑数据朝向强制为 `0`。编辑器不再提供建筑旋转控件；新建、生成、导入和旧地图解析都会归零。
- 只有带建筑模型 `asset` 的真实建筑遵守此规则。海岸、道路和水域使用的无模型碰撞代理保留自己的几何方向。
- 3D 操作只产生地图语义命令，最终仍写入 `OrchardMap`；Three.js 对象变换不是持久化数据。
- 2D 继续负责海岸节点、自交检查和精确拓扑；3D 负责直觉化放置、选择、移动和空间检查。

## 已实现的桌面工作流

| 操作 | 3D 支持 | 数据处理 |
| --- | --- | --- |
| 选择与拖动 | 建筑、池塘、普通地块、投递点、视觉区域、矩形障碍、水面、桥梁 | X/Z 地面拖动；移动前用草稿地图校验 |
| 直接放置 | 树木、擦除、道路节点、建筑、池塘、果园/草地、果实、角色起点、投递点、岛屿结构 | 使用现有编辑命令和限制，不直接修改渲染物体 |
| 精确编辑 | 建筑、池塘、地块、投递点可输入 X/Z；岛屿结构沿用结构属性面板 | 成功时产生一条撤销记录 |
| 复制与删除 | 建筑、池塘、地块、投递点、岛屿结构 | 自动寻找附近合法位置；删除后重新验证地图 |
| 非法反馈 | 拖动预览变红，松手后恢复 | 不污染地图和撤销历史 |
| 桥梁约束 | 只允许沿所属水面的 X 轴移动 | 自动重算水域碰撞缺口 |

3D 道路使用逐点点击：第一次确定起点，后续点击追加路段。树木和擦除使用当前画笔半径，可连续点击不同位置。切换工具或视图会结束当前 3D 道路链。

## 状态边界

```text
3D 拾取 / 地面拖动 / 放置
        ↓
编辑器语义命令
        ↓
OrchardMap 草稿
        ↓
结构同步 + 可游玩性校验
        ↓
一次历史提交
        ↓
2D 与 3D 共同重建
```

拖动过程中只移动高亮代理，不在每个 `pointermove` 重建完整世界。松手并通过校验后才重建场景，避免模型加载、撤销和碰撞状态分叉。

## 为什么不使用第三方编辑器作为主流程

- [Three.js Editor](https://threejs.org/editor/) 能编辑普通场景树和导出 glTF/GLB，但不了解投递点顺序、水域派生碰撞、稳定 ID 和可游玩性规则；仍需维护完整的双向转换器。
- [Blender glTF](https://docs.blender.org/manual/en/3.3/addons/import_export/scene_gltf2.html) 可通过自定义属性导出 `extras`，适合以后由美术单向导入大型布景，但不适合作为日常玩法地图真源。
- [PlayCanvas Editor](https://developer.playcanvas.com/user-manual/editor/interface/viewport/) 有成熟的场景层级与操作柄，但会引入另一套引擎、场景格式和服务依赖。

因此当前方案使用 Three.js 自身的射线拾取能力，并在项目内实现面向 `OrchardMap` 的小型语义编辑层。以后如需 Blender 支持，应定位为“单向布景导入”，而不是替换地图规则编辑器。

## 暂不纳入

- Blender 式自由旋转、任意缩放和通用场景树。
- 框选、多选和批量对齐。
- 在 3D 中编辑海岸多边形节点；这类拓扑操作继续留在 2D。
- 移动端布局与触控优化。
