# Apple Picking 免费素材接入与低风险实施计划

- 日期：2026-08-15
- 状态：讨论稿，等待逐阶段确认
- 范围：免费素材筛选、接入、验收和回退；本方案不直接改变玩法规则
- 关联文档：[视觉精修与状态表现方案](./2026-08-15_apple-picking-visual-polish-plan.md)

## 1. 目标

在保持当前低多边形果园风格、移动端全屏地图和清晰玩法反馈的前提下，适量使用许可明确的免费素材，提高声音、环境轮廓、角色动画和材质层次。

这次优化不追求“素材越多越好”，而是优先补足玩家最容易感知、同时最不容易破坏现有体验的部分。所有措施都应可以单独接受、调整或放弃。

## 2. 决策原则

1. **低风险优先**：先声音，再场景局部替换，再做单个角色验证；不进行一次性的整体换皮。
2. **玩法与表现分离**：素材只替换视觉或听觉表现，不改变 `GameSimulation`、碰撞半径、寻路空间和胜负规则。
3. **保留回退路径**：接入期间保留现有程序化模型和声音，每阶段用开关或清晰的资源入口进行 A/B 对比。
4. **先小样、后批量**：每类素材只选择一个最小样本，经过桌面与手机画面验收后才扩展。
5. **统一美术来源**：同一类 3D 资产优先只使用一个素材系列，避免 Kenney、KayKit、Quaternius 的造型语言混杂。
6. **许可先于下载**：只有许可证、来源页和使用范围记录清楚的素材才进入仓库。
7. **真实尺寸验收**：所有视觉决定以实际手机视口中的轮廓和状态可读性为准，而不是只看模型预览图。

## 3. 当前基线与不可破坏的特征

### 3.1 当前基线

当前版本已经具备：

- 地图覆盖完整视口，HUD 透明叠加在地图上方；
- 外围房屋和装饰树木已移除，屏幕内容集中在玩法区域；
- 暖色、低多边形、桌面微缩景观式的视觉方向；
- 约 61 个 draw call、4,638 个三角面、57 个 geometry、3 张纹理；
- 角色待机呼吸、负重姿态、苹果堆叠和滴汗；
- guard 飞扑、落地和爬起表现；
- 人物与苹果碰撞、苹果被轻推开的反馈。

### 3.2 必须保留的细节

外部素材不能削弱以下信息：

- kid 的空手、少量携带和大量携带必须一眼可分辨；
- 大量携带时仍需保留身体前倾或重心变化、苹果堆和滴汗；
- guard 的飞扑、爬起和正常移动不能混淆；
- 角色阵营色、帽子或其他身份锚点必须在手机尺寸下可见；
- 苹果仍然是轻量物体，外观替换不能暗示其具有很大质量；
- 树木等障碍只替换外观，不改变通行空间和碰撞结果；
- 不重新添加地图之外的房屋、树群或其他外围装饰。

### 4.1 许可策略

第一阶段只接受 CC0 素材。这样可以降低署名遗漏、分发限制和后续换平台时的合规风险。

CC-BY 素材只有在没有合适 CC0 替代品、且用户明确接受署名要求后再考虑。CC-BY-NC、来源不明、由第三方重新打包但没有原始授权页面的素材不进入项目。

## 5. 哪些内容适合使用外部素材

### 5.1 建议替换或补充

- **事件音效**：最容易提升完成度，几乎不影响玩法和画面结构；
- **果园内部树木轮廓**：用少量统一模型替换现有障碍外观，可增加形状变化；
- **单个 guard 的角色和动画小样**：验证外部角色能否承载飞扑、爬起和身份识别；
- **轻量环境光或材质噪声**：只在前面效果稳定后做 A/B 测试。

### 5.2 建议继续程序化或自定义

- 苹果、篮子和携带中的苹果堆；
- 滴汗、碰撞、交付、飞扑等状态特效；
- 碰撞代理、角色状态机和移动逻辑；
- HUD 布局和透明覆盖方式；
- 地图边界、通道和障碍的实际占地；
- 角色身上的身份锚点和用于挂接苹果、帽子、汗滴的 socket。

这些内容与玩法可读性紧密相关，直接套用素材包通常会失去现有的关键细节。

## 6. 风险分级

| 措施 | 玩家收益 | 实施风险 | 主要风险 | 建议顺序 |
| --- | --- | --- | --- | --- |
| 6–10 个事件音效小样 | 高 | 低 | 音量失衡、重复疲劳 | 1 |
| 3 个内部树木外观小样 | 中高 | 低至中 | 遮挡角色、风格不统一 | 2 |
| 单个 guard 角色小样 | 高 | 中高 | 状态动作不匹配、素材包感过强 | 3 |
| 第二个 guard 与 kid 全面替换 | 高 | 高 | 携带状态和身份识别退化 | 4，条件执行 |
| 低分辨率 HDRI/材质层次 | 中 | 中 | 破坏微缩低多边形风格、增加开销 | 5，条件执行 |
| UI 图标和触控提示包 | 中 | 中 | 当前触控方案尚未定型，可能返工 | 延后 |
| 多素材包混用、完整素材包导入 | 低或不确定 | 高 | 风格碎片化、包体和维护成本上涨 | 不建议 |

## 7. 建议实施计划

每一阶段都形成独立提交和独立验收点。上一阶段被接受，不代表后续阶段自动执行。

### 阶段 0：资产台账与基线锁定

**风险：极低。建议首先实施。**

范围：

- 新建 `docs/ASSET_LICENSES.md`，记录真正被采用的外部素材；
- 定义最小资产目录和命名约定，但不预先建立复杂加载框架；
- 保存当前桌面和手机关键状态截图及渲染统计，作为 A/B 基线；
- 明确下载包只作筛选，仓库只保留实际使用的文件和许可证说明。

资产台账至少包含：

| 字段 | 内容 |
| --- | --- |
| 资产名称 | 包名和具体文件名 |
| 作者/来源 | 官方作者与原始资产页 |
| 许可证 | CC0 或其他明确许可 |
| 获取信息 | 下载日期、版本号或页面状态 |
| 修改说明 | 裁剪、降采样、转码、重新打包等 |
| 项目路径 | 最终进入仓库的文件位置 |
| 使用位置 | 对应事件、实体或界面 |

验收：仅有文档和基线，不改变游戏运行结果。

决策点：确认台账格式后进入声音小样；若不接受，删除文档即可，不影响项目。

### 阶段 1：声音最小小样

**风险：低。推荐作为第一个可感知改动。**

范围：从 Kenney CC0 音效中只选择 6–10 个短音效，覆盖：

- 苹果拾取；
- 苹果掉落或被推动；
- guard 飞扑启动与落地；
- guard 爬起完成；
- kid 被抓；
- 苹果交付；
- 最后几秒倒计时或回合结果。

实施约束：

- 保留现有程序化声音作为回退；
- 一个事件族先接入一个声音，不同时重做全部音频系统；
- 对高频事件准备 2–3 个轻微变体，或使用很小的音高变化减少重复感；
- 对素材做裁剪、响度统一和 OGG 转码；
- 首批压缩音频总量建议不超过 1.5 MB；
- 不加入背景音乐和长环境音，避免掩盖玩法反馈。

验收标准：

- 只听声音也能区分拾取、飞扑、被抓和交付；
- 高频拾取不会刺耳或产生明显听觉疲劳；
- 浏览器首次交互后的音频解锁、暂停和重开正常；
- 关闭外部音效后，游戏退回现有行为；
- 构建和完整测试通过。

决策点：用户对小样选择“接受、调整或撤回”。只有接受后才进入场景素材。

### 阶段 2：内部树木轮廓小样

**风险：低至中。只替换视觉，不改变障碍。**

范围：

- 从 KayKit Forest 中选 3 个同系列树木模型；
- 只替换果园内部现有树障碍的可见网格；
- 可选地加入最多 2 种很小的草丛，但只能靠近围栏或障碍，不能污染通道；
- 不增加外围树木、房屋或地图外装饰；
- 不改变碰撞形状、障碍位置和地图路线。

实施约束：

- 使用现有障碍节点作为 transform wrapper，外部 GLB 只是子级视觉；
- 重复树木使用共享 geometry/material，数量合适时使用 instancing；
- 只保留一个共享图集，优先降到 256 或 512 像素；
- 保留现有程序化树木开关，以便同一机位 A/B 对比；
- 不为了模型造型去修改摄像机、角色碰撞或关卡布局。

建议小样预算：

- draw call 不超过 75；
- 可见三角面不超过 25k；
- 纹理不超过 5 张；
- 新增模型与纹理合计不超过 2 MB；
- 手机视口中角色不能被树冠长期遮挡。

验收标准：

- 390 × 664 等窄屏下，人物、苹果、篮子和通道仍清楚；
- 树木轮廓比当前版本更丰富，但仍属于同一个果园；
- 路线、碰撞和苹果推移结果与基线一致；
- 实际运行截图比模型单独预览更好看；
- 性能统计和测试通过。

决策点：并排查看程序化版与素材版。若收益不足，撤回外部树木，不影响声音阶段。

### 阶段 3：单个 guard 角色验证

**风险：中高。一次只验证一个角色。**

范围：

- 优先选择一个 KayKit Adventurers 角色；不合适时再试 Quaternius；
- 只替换一个 guard，另一名 guard 和 kid 保留原样作为对照；
- 接入待机、移动、飞扑、落地、爬起和受控状态所需的最少动画；
- 继续使用现有模拟层的圆形碰撞和位移结果。

实施约束：

- 优先使用原地动画，由游戏逻辑控制移动，避免 root motion 改变规则；
- 模型建立命名明确的头、背、手等挂点，继续承载帽子、汗滴、苹果或特效；
- 阵营色和身份轮廓必须可调整，不能完全依赖模型包原色；
- 单角色建议 5k–15k 三角面、单材质、单图集；
- 单个整理后的 GLB 建议不超过 1.5 MB；
- 加载失败时显示原有程序化角色，不能出现隐形角色。

验收标准：

- 手机尺寸下，待机、追赶、飞扑和爬起的状态比原版更清楚；
- 爬起不能被误读为眩晕或死亡；
- 外部角色没有明显的通用奇幻素材包感；
- 角色颜色、帽子和动作仍能快速表达 guard 身份；
- 动画切换无明显滑步、跳帧或初始 T-pose；
- 性能、加载、重开和碰撞回归测试通过。

决策点：

- **接受**：将相同角色管线扩展到第二个 guard；
- **调整**：只修改材质、比例或动画映射后重新评估；
- **拒绝**：恢复程序化 guard，停止角色替换，不影响前两阶段。

### 阶段 4：角色扩展

**风险：高。仅在阶段 3 明显成功后实施。**

建议顺序：第二个 guard，然后才是 kid。

kid 最后处理，因为它需要同时表达：

- 空手、拾取中、少量携带和大量携带；
- 负重姿态和移动速度感；
- 苹果堆、背部挂点和滴汗；
- 被追赶、被抓和交付状态。

如果外部角色无法稳定承载这些状态，应保留现有 kid，允许场景与 guard 使用外部素材而主角继续程序化建模。

决策点：每个角色单独验收，不以“已经做了角色管线”为理由强制全部替换。

### 阶段 5：光照与材质微调

**风险：中。可选阶段。**

范围：

- 对比当前环境光与一张 256 像素左右的中性 CC0 HDRI；
- 或只给草地、木材增加非常轻的粗糙度/颜色变化；
- 不使用可见的照片天空，不引入写实背景；
- 暂不加入景深、Bloom、SSAO 等后处理链。

验收标准：明暗层次更稳定，角色和苹果没有变灰，移动端性能无明显下降。收益不明显时直接保留当前光照。

### 延后阶段：触控 UI 素材

等触控方案和手机操作方式稳定后，再考虑 Kenney Input Prompts 或 UI Pack。现在提前接入很可能因按键布局变化而返工。

## 8. 建议目录与导入流程

仅在第一批素材真正被接受时创建相应目录，避免空架构：

```text
public/assets/
  audio/
  models/environment/
  models/characters/
  textures/
docs/
  ASSET_LICENSES.md
```

推荐导入流程：

1. 从作者或项目的官方页面下载；
2. 在仓库外解压和筛选，不把整个素材包直接提交；
3. 保存原始许可证或在资产台账中记录官方许可页面；
4. 删除未使用的模型、动画、材质和高分辨率贴图；
5. 统一坐标、比例、命名、材质和动画片段；
6. 3D 资产整理为 GLB，音频裁剪并转为适合网页的 OGG；
7. 只把最终使用的资产和必要许可记录加入仓库；
8. 运行构建、测试、手机视口检查和渲染统计；
9. 单独提交，等待用户确认后再进入下一阶段。

不建议在第一阶段建立复杂的通用资产系统。只有在第二种外部素材证明需要复用加载逻辑时，才新增最小 manifest 或 registry。

## 9. 总体移动端预算

以下是接入后的建议目标，不是要求每阶段都用满：

| 指标 | 建议目标 | 说明 |
| --- | --- | --- |
| Draw calls | 目标不超过 100，硬上限 150 | 当前约 61，需保留余量 |
| 可见三角面 | 不超过 80k | 场景和所有角色合计 |
| 运行时纹理 | 不超过 12 张 | 优先共享图集 |
| 阴影光源 | 1 个 | 不增加额外投影灯 |
| DPR | 不超过 2 | 延续当前移动端策略 |
| 单角色三角面 | 5k–15k | 以轮廓和动画质量优先 |
| 单角色材质 | 1 个优先 | 避免 draw call 膨胀 |
| 首批新增资产体积 | 建议不超过 6 MB | 含模型、贴图和短音效 |
| 首批压缩音频 | 建议不超过 1.5 MB | 不含未来背景音乐 |

## 10. 每阶段统一验证清单

### 自动检查

- `npm run build`
- `npm test`
- `npm run verify:visual`
- `npm run inspect:canvas -- --state heavy-carry`
- 对应的窄屏 canvas 检查

### 关键人工画面

- 正常游戏中的桌面视图；
- 390 × 664 左右的手机竖屏视图；
- kid 大量携带与滴汗；
- guard 飞扑；
- guard 爬起；
- 苹果交付进度；
- 多角色接近、碰撞和苹果被推开。

### 每次记录

- 外部资产开关前后的同机位截图；
- draw call、三角面、geometry 和纹理数量；
- 新增压缩资源体积；
- 控制台错误和资源加载失败；
- 玩法规则测试是否完全未变。

## 11. 明确不建议现在实施的措施

- 一次性替换所有人物、树木、苹果和 UI；
- 同一场景混用多个低多边形素材包；
- 把完整 ZIP 或大量未使用模型提交到仓库；
- 使用高分辨率 PBR 贴图装饰小尺寸手机画面；
- 使用 HDRI 作为可见背景，重新占用地图之外的视觉空间；
- 重新添加外围房屋、树群和与玩法无关的环境叙事；
- 让模型碰撞体直接决定玩法碰撞；
- 让 root motion 控制角色实际位移；
- 在没有许可记录时提交素材；
- 把 Mixamo 或含非商业限制的素材作为核心依赖。

## 12. 推荐决策顺序

当前最稳妥的推进顺序是：

1. **批准阶段 0**：只建立资产台账与验收基线；
2. **批准阶段 1 小样**：先接入 6–10 个 Kenney CC0 事件音效；
3. 听感确认后，再决定是否做 **阶段 2 的 3 棵树视觉小样**；
4. 只有场景风格方向稳定后，才投入 **阶段 3 的单 guard 原型**；
5. kid、光照、材质和触控 UI 均延后，由前面小样结果决定是否值得继续。

建议下一步只实施阶段 0 和阶段 1，不下载或替换任何角色模型。这样可以用最小代码和资产改动验证“外部素材能否提升质感”，也保留最完整的撤回空间。
