# KayKit 世界迁移：持续迭代记录

> 状态：进行中。本文件是大规模地图美术与编辑器升级的单一事实来源；每轮实现、验证结果和下一步都在这里追加，不另写互相冲突的方案。

## 目标与不变量

把 KayKit Medieval Builder Pack 从“单栋房屋替换”提升为主要世界套件，同时保留《Apple Picking》的核心循环：小偷在连续、开阔的地形中拾取苹果并送达，守卫依靠追逐和扑击阻止投递。世界可以更丰富，但不能牺牲角色辨识度、路线选择或碰撞可信度。

本阶段保持以下不变量：

- 竞技场仍是 72 × 54，角色尺寸和现有镜头不变。
- 房屋、院落和水面不可进入；视觉模型必须和已有碰撞语义对齐。
- 苹果可以略大，以符合当前轻松、玩具感的美术风格。
- 树桩缩小且以低矮障碍为主，大树只作为少量方向标和边缘轮廓。
- 路线是宽阔的活动带，不是树墙夹出的窄线。
- 小河延后到地图格式能够表达水域、河岸和桥梁通行规则以后。

## 第一轮：可玩视觉试验场

入口统一使用主游戏，不做只能旋转观看的静态展台。KayKit 村庄已经成为默认入口，避免只有知道查询参数的人才能看到：

- `/`：林间村落。默认使用方形地块、宽路、集市/农田/伐木场地标。
- `?world=medieval&layout=riverside`：河畔集市。沙土地、池塘水面、水车/磨坊/集市地标。当前只有池塘，不承诺可跨越河流。
- `?world=medieval&layout=fortified`：城堡果园。岩石边缘、城堡/兵营地标、远端城墙和门楼。
- `?world=custom`：载入地图编辑器当前地图，并按其中保存的 KayKit 主题、地块形状和建筑模型渲染。
- `?world=classic`：旧果园对照入口。

三套候选都复用同一套确定性规则，只改变地图种子、宽路/空地和世界美术组合。KayKit 源包同时包含六边形和方形地块；当前默认使用更适合正交建筑布局的方形地块，六边形作为编辑器可选项保留，两者都使用实例化渲染。完整 226 个 GLB 已发布到运行时资产库，并由 `catalog.json` 按 objects / hex / square 分类；地图按语义选择合适模型，不把 226 件互不相干的模型同时堆在同一竞技场。

### 碰撞与视觉契约

- `homestead` 地标：渲染为 KayKit 建筑，建筑整体位于不可进入矩形内。
- `pond` 地标：六边形水面只铺在不可进入椭圆内，岸边用过渡地块和岩石提示。
- 树木：继续使用已有树碰撞和自然包模型，下一轮根据选定风格决定是否统一为 KayKit 森林。
- 边界城墙：只放在现有竞技场夹紧边界上，不在内部制造“看似阻挡但可穿过”的墙。
- KayKit 世界加载失败：保留现有程序化地面、路径、围栏和地标作为完整回退。

### 当前优先级

- 第一优先级是可玩性：目标可达、竞技区域开阔、至少存在多条有效接近路线、不可进入区域有可信碰撞。
- 第二优先级是世界辨识度：村落、河畔和城堡应当只看画面轮廓就能区分，而不是换几块地表颜色。
- 226 个模型全部保留为可用素材库；生成器根据地表邻接、建筑槽位和地图主题选择子集。
- 本阶段不以移动端资源请求、draw calls、三角面和包体预算限制地图设计；自动诊断继续记录数据，但不作为候选淘汰条件。
- 性能优化移到世界方向和编辑器工作流稳定之后，再做实例化、LOD、按需加载和移动端降级。

## 地图 v5 预留：多个投递区

第一轮不改规则层，避免把视觉选择和存档迁移绑在一起。选定世界方向后，v5 将把单个字段：

```ts
deliveryZone: Vec2
```

升级为：

```ts
deliveryZones: Array<{
  id: string;
  x: number;
  z: number;
  radius: number;
}>
```

拟定规则如下：

- 所有投递区等价；进入任意一个都可投递。
- 投递区重叠时先选最近中心，再按 `id` 稳定排序。
- 苹果位于任意投递区内都保持“已送达”；离开所有投递区才失去该分。
- 事件携带 `zoneId`，便于 HUD、音效和统计定位。
- v4 单投递区自动迁移为含一个元素的数组。
- 数量由地图尺寸和预设推导，默认 72 × 54 地图建议生成 2 个，但不写死为固定数量。

## 编辑器方向（第三、四轮）

编辑器最终保存语义而不是具体 GLB 文件名：森林、道路、沙地、岩地、水域、院落、建筑槽位和投递区。渲染层负责把语义自动拼成 KayKit 地块，避免用户逐格挑选 `roadA` 到 `roadM`。

需要的编辑能力：

- 地表语义画笔与道路/岸边自动拼接。
- 建筑/院落的占地预览、碰撞范围和比例参考人形。
- 多投递区的添加、移动、半径调节和删除。
- 2D 快速编辑与 3D 即时预览切换。
- 随机候选继续保留，但生成“区域骨架 → 地标 → 宽通路 → 装饰”，不再用树桩填满剩余空间。

### 当前可用的人工搭建流程

1. 打开 `/editor.html`，在“KayKit 世界样式”中选择林间村落、河畔集市或城堡果园。
2. 地块形状默认选择“方形地块”；需要比较旧效果时可切换为六边形。
3. 选择“铺设宽路”后拖动绘制道路骨架。方格地图会把输入吸附为水平/垂直折线，渲染层再根据四邻接自动选择 KayKit A–E 直路、转角、T 口和十字路口。
4. 选择“KayKit 建筑”，再选择具体模型与 0° / 90° / 180° / 270° 朝向，点击画布放置。编辑器不会保存任意斜角建筑。
5. 用池塘、果园地块、草地空场、树木和出生/目标工具补齐规则内容；保存前继续执行可达性校验。
6. 在画布上方切换“3D 预览”，用左键拖动旋转、滚轮缩放、右键平移；切回“2D 编辑”后继续放置。
7. 点击“使用并游玩”，进入 `/?world=custom` 检查真实碰撞、镜头遮挡和完整游戏循环；左上角“编辑”可返回继续调整。

当前 3D 视图是同步的视觉检查器，放置、拖动和删除仍在 2D 视图完成。这是有意的范围边界：先让构图判断可靠，再决定是否值得开发完整的 3D 拖拽工具。

## 验证记录

本节在每轮结束后填写构建、测试、桌面/窄屏截图检查、renderer 指标和仍需人工试玩的风险。

### 2026-08-16 · 第一轮

- 实现：三套候选、主游戏切换导航、实例化六边形地块、语义地标建筑、水面/边界墙、诊断与完整程序化回退均已接入；实验地图不写入本地存档。
- 资产：精选 24 个 GLB，共 1,139,308 bytes；单套候选实际请求 7–12 个。
- 构建与测试：`npm run build` 通过；新增桌面/窄屏候选矩阵、地图可达性和资源失败回退覆盖；完整结果以本轮最终验证为准。
- 桌面 1280 × 720：顺序稳态检查为 60 FPS，draw calls 62–81，三角面约 71k–81k，均低于本轮预算；并行启动多个 WebGL 检查页会短暂争用同一 GPU，不计作单实例性能。
- 窄屏 390 × 664：三套候选均为非空可辨识画面，候选切换器与地图入口移到安全区底部；世界试验默认收起开发调试面板，添加 `debug` 查询参数可重新显示。
- 已知取舍：道路暂用宽沙土地块表达连通活动带，尚未使用 `roadA`–`roadM` 自动拼接；水域仍只有池塘，不伪装成已具备桥梁规则的河流。
- 下一轮决策：等待三套候选实机评价，再确定主方向、建筑密度和地块层次；随后进入地图 v5 与多投递区。

### 2026-08-16 · 完整素材库与默认入口修正

- 发现问题：先前 `/` 仍指向旧果园，KayKit 试验只能通过隐藏查询参数进入，导致正常打开方式看不出变化。
- 入口修正：`/` 默认进入林间村落；顶部可直接切换另外两张 KayKit 候选；`?world=classic` 保留旧果园与编辑器保存地图。
- 资产策略：取消“只复制 24 个文件”的发布限制，完整接入 objects 30、hex 128、square 68，共 226 个 GLB、3,965,144 bytes，并生成机器可读目录。
- 画面扩充：三张地图分别加入村舍/靶场/农田、桥梁/水车/磨坊、城堡/兵营/矿山/多种城墙等外围建筑群。外围模型不侵入竞技区域；内部建筑仍必须绑定现有不可进入地标。
- 测试策略：继续验证三张地图全部关键目标可达、真实键盘移动和加载失败回退；移除候选场景的移动端渲染预算淘汰条件，并新增全部 226 个运行时文件可访问检查。
- 验证结果：`npm run build`、`npm run verify:visual` 和完整 `npm test` 均通过；完整测试为 41 passed、33 skipped，桌面浏览器三套候选无控制台错误。
- 后续：完整目录将在地图 v5 编辑器中转化为语义资产面板与自动拼接规则；“完整库可用”不等于在单张地图中无差别展示全部文件。

### 2026-08-16 · 方格与人工建筑编辑

- 建筑方向：所有生成建筑、外围建筑和编辑器建筑都限制为四个正交方向，避免在斜视镜头下出现歪斜、互相不齐的村落轮廓。
- 地块选择：接入源包中的 square 地块并设为默认；hex 地块继续保留，选择会写进地图而不是只影响编辑器缩略图。
- 编辑器：加入 3 套世界主题、12 类 KayKit 建筑、4 个固定朝向和方格/六边形选择；随机候选继承这些选择，已保存地图会显示对应主题与地块信息。
- 试玩闭环：点击“使用并游玩”进入 `/?world=custom`，渲染当前编辑地图；默认入口的顶部导航也提供“我的地图”。
- 调试：KayKit 地图不再默认隐藏开发调试窗口，普通入口和编辑器试玩入口均可直接调镜头、速度与光照。
- 范围说明：本轮解决的是“能人工搭、能选具体资产、能直接试玩”的工作流；现有随机构图的审美问题并未宣称解决，道路/院落自动拼接与 3D 编辑预览仍是后续迭代。
- 验证：`npm run build`、完整 `npm test`（42 passed、34 skipped）和 `npm run verify:visual`（19 passed、13 skipped）均通过；浏览器实机确认 `/editor.html` 控件完整、`/?world=custom` 使用当前地图且开发调试窗口可见。

### 2026-08-16 · 3D 预览与方格道路骨架

- 编辑器：增加实时 2D / 3D 切换；3D 视图复用主游戏的 KayKit 世界与 Nature Pack 树木渲染，并显示角色比例、苹果和投递圈。支持旋转、缩放和平移，不需要进入主游戏才能判断构图。
- 道路：方格主题使用 KayKit `roadA`–`roadE` 资产按四邻接拓扑自动选择端点、直路、转角、T 口和十字路口。新增“铺设宽路”工具（E），方格模式自动正交吸附。
- 生成器：候选地图先生成 2 条跨场主路，再从房屋添加正交支路；道路上的树桩和树木会被清理，不再用高密度树桩勾出狭窄“线路”。
- 构图：房屋周边生成尺寸受控的沙地院落；城堡主题在四边生成对齐的围墙、墙角和与道路对应的门洞。移除了边缘被镜头裁切的整排建筑，也取消了曾造成“棋盘补丁”的大面积沙色地形转换。
- 视觉边界：当前已经比纯树桩填充有更清楚的路网、院落和边界，但随机候选仍不等于人工关卡。池塘形状、建筑组合变化和地表层次仍是下一轮的主要审美短板。
- 自动验证：`npm run build` 通过；完整 `npm test` 为 42 passed / 34 skipped；`npm run verify:visual` 为 19 passed / 13 skipped。`npm run inspect:canvas` 确认默认画面非空、无控制台/页面错误，桌面默认场景为 90 draw calls、71,203 三角面、129 geometries 和 12 textures，均在现有诊断预算内。
