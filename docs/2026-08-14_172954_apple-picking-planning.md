# Three.js 双人躲避取苹果游戏：启动讨论记录

> 记录时间：2026-08-14
> 关键词：kid vs guard1/guard2、苹果运送、追逐、飞扑、撞晕、胜负条件

## 1) 结论先行（本轮启动决策）
- 采用 **3D 等距俯视 + 边界网格地形 + 轻量碰撞** 的第一版原型。
- 核心循环先不做复杂 AI/动画过渡：优先做可玩性闭环。
- 游戏目标以「kid 成功送完苹果」或「kid 被抓 3 次」结束。

## 2) 角色与规则确认（由讨论“熔炼”后确定）
### 2.1 玩家职责
- 玩家 A：控制 `guard1` 与 `guard2`（共享键位方案）。
- 玩家 B：控制 `kid`。

### 2.2 苹果与速度机制
- kid 每捡到 1 个苹果，移动速度按线性下降（如每个 `-10%`），可设上限/下限防止过慢。
- 每次在场景按键“丢弃一颗苹果”：
  - 仅允许一次抛弃 1 个。
  - 丢弃后速度 **立即恢复一档**（可理解为增加一个苹果对应的速度衰减档位）。

### 2.3 guard 飞扑
- 飞扑是“短时高速度突进 + 复位延迟”的能力：
  - 按键触发后瞬发一个 `dodgeDistance` 位移。
  - 进入飞扑会有 `cooldown` 与 `recoverTime`（起身时间）。
- 若 **同一帧/短时窗口** 同时接触 `kid` 的是两个 guard，则双方进入“头晕”状态（例如 1.5~2s）并失去抓捕能力。

### 2.4 抓捕与生命
- 只要 `kid` 与任一 guard 碰撞 -> kid 被抓。
- 被抓 3 次 -> A 获胜。
- 被抓时可触发：kid 重生或无敌短暂恢复/轻微击退（先定性）并重置抓捕计数逻辑。

### 2.5 结束条件
- B 胜：场上所有苹果已放入目标点。
- A 胜：kid 被抓满 3 次。

## 3) 技术实现起步方案（最小可运行版本）
- 引擎：Three.js + cannon/eslint?（先不引入重物理，第二阶段再接）。
- 第一版位置逻辑采用：
  - `Vector3` 运动 + 圆形碰撞（`distance <= radius`）。
  - 地面用可见平面 + 冲突箱体边界。 
- 状态管理：
  - `GameState`: PLAYING / WIN_KID / WIN_GUARD / PAUSED
  - `RoundState`: kid持果数、已交付数、抓捕次数、技能冷却。

## 4) 里程碑（建议）
1. 第1周：场景、角色控制、移动与碰撞、苹果拾取与投递闭环。
2. 第2周：飞扑 + 头晕机制 + 抓捕计数。
3. 第3周：速度衰减/恢复、UI（计时/计数）和胜负界面。
4. 第4周：平衡参数打磨 + 音效/动效 + 本地化键位。

## 5) 需要你确认的问题（grill-me 风格）
- 输入方式：A 的两个 guard 是键位共用（轮流切换）还是并行双摇杆？
- 飞扑接触窗口多久算“同时接触”？（建议 120~180ms）
- 被抓后 kid 重生是否要回到出生点？每次重生是否有时间惩罚？
- 目标点为单点圆环区域还是可站立平台？
- 你希望是本地双人同机键盘，还是以后扩展网络联机？
