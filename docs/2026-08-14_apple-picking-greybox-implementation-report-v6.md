## 1. 结果摘要

- 已建立 Vite + TypeScript + Three.js 工程，并把脚手架示例替换为本项目的双人共享屏玩法。
- `kid` 拾取规则已按最新裁决实现：按键后进入 `Picking`，停留 `400ms / 24 ticks`，期间不能移动但仍可被抓；抓捕会取消拾取。
- `Right Shift` 为即时扔果动作：交付区外每次丢弃一个，区内每次主动送达一个；两者都不进入状态、不停留、无冷却，可快速重复按键。
- 苹果、抓捕、飞扑、恢复、双 guard 互撞眩晕、无敌、交付、胜负、倒计时与重开均已形成可玩闭环。
- 比赛不设时间上限或平局；HUD 的“用时”只正向累计，直到一方达成胜利条件。
- 自动化构建、确定性规则、系统 Chrome 桌面/窄屏、非空画布和渲染预算检查均通过。
- 尚未完成五局真人双人试玩，因此当前结论是“可进入试玩”，不是“平衡完成”或“发布就绪”。

## 2. 游戏设计简报与核心循环（Game Design Brief）

### 玩家承诺

- 玩家 A 同时操控两名苹果园守卫，通过站位、夹角和飞扑围捕 `kid`。
- 玩家 B 操控偷苹果的 `kid`，在停留拾取、负重减速、即时丢果和送达路线之间承担风险。
- 目标情绪为欢乐闹剧、主动快乐、轻娱乐；苹果只属于 `kid` 的目标系统，guard 不与苹果发生规则交互。

### 核心循环契约（Core Loop）

```text
守卫：移动与飞扑形成包夹 -> 利用 kid 的拾取停留和负重路线完成接触抓捕
-> 累计三次获胜；飞扑落空、恢复和互撞眩晕给 kid 反制机会。

kid：靠近苹果并停留拾取 -> 决定继续负重、快速丢果提速或前往交付区逐个主动送达
-> 全部送达获胜；每次被抓会掉落全部携带苹果，三次被抓后失败。
```

### 首个竞技场（Level/Encounter Plan）

- `24m x 18m` 固定果园竞技场，固定等距俯视镜头。
- 六个苹果、三组果树障碍与一处圆形交付区。
- 交付区以浅漏斗地面造型呈现，但模拟层只使用半径 `2m` 的圆形传感器。
- `kid` 与两名 guard 从分离区域开始；障碍提供绕行、夹击和换向路线。
- 当前空间已证明可渲染和可移动，路线强弱仍需真人试玩验证。

## 3. 已实现规则

### 输入

| 角色 | 移动 | 动作 |
| --- | --- | --- |
| 蓝守卫 | `W A S D` | `Q` 飞扑 |
| 绿守卫 | `I J K L` | `P` 飞扑 |
| `kid` | 方向键 | `Right Ctrl` 拾取、`Right Shift` 区外丢果 / 区内送达 |
| 全局 | - | `R` 重开 |

- 斜向输入归一化。
- 输入区分按下沿与持续状态；窗口失焦或页面隐藏时清空，避免卡键。
- 首版明确为同键盘桌面游戏；窄屏项目只验证画面和 HUD 适配，不宣称触屏或 Safari 支持。

### 权威模拟

- 固定 `60Hz`，渲染帧与规则 tick 分离。
- 状态：`MatchState`、`GuardState`、`KidState`、`AppleState`。
- 自定义 XZ 圆形/AABB 碰撞，Three.js 网格不拥有规则状态。
- 飞扑接触使用固定步中的相对线段距离检查，避免快速接触只看帧末位置。
- 所有计时使用 tick；实体使用稳定 ID；散落随机经过可设种子的 RNG。
- 规则顺序为区外即时丢弃或记录区内送达请求、开始拾取、移动、场地碰撞、guard 互撞、抓捕、完成拾取、主动送达、胜负。
- 第三次抓捕与最后一次主动送达同 tick 时，抓捕优先。

### 当前数值

| 参数 | 实现值 |
| --- | ---: |
| `kid` 基础速度 | `4.8m/s` |
| guard 基础速度 | `4.2m/s` |
| 每个苹果减速 | `10%`，最低 `55%` |
| 拾取停留 | `400ms / 24 ticks` |
| 飞扑 | `9m/s`，持续 `13 ticks` |
| 飞扑恢复 | `42 ticks / 700ms` |
| 恢复后冷却 | `36 ticks / 600ms` |
| 双飞扑窗口 | `9 ticks / 150ms` |
| 互撞眩晕 | `60 ticks / 1000ms` |
| 抓捕后无敌 | `72 ticks / 1200ms`，速度 `1.25x` |

## 4. 代码边界

```text
src/core/InputRouter.ts       多角色输入与按下沿
src/game/config.ts            权威数值、出生点、障碍与苹果布局
src/game/types.ts             命令、状态、快照与领域事件
src/game/GameSimulation.ts    固定步规则与确定性测试场景
src/game/Game.ts              模拟、渲染、HUD、音频和诊断编排
src/render/ArenaView.ts       果园灰盒、角色、苹果、交付区和状态可视化
src/systems/Hud.ts            比赛进度、状态、倒计时与胜负界面
src/systems/AudioSystem.ts    事件驱动的程序化占位音效
tests/game-rules.spec.ts      关键规则回归
tests/visual.spec.ts          系统 Chrome 画布、输入和 HUD 适配冒烟测试
```

`GameSimulation` 是规则唯一所有者；渲染层只消费快照。测试钩子可以载入确定性场景、逐 tick 推进并读取快照，为后续联机和回归测试保留了边界。

## 6. QA 决策

- 视觉测试：已加入确定性场景、非空像素、输入位移、桌面/窄屏 HUD 适配冒烟测试。
- 像素基线：暂不加入。灰盒布局和模型仍会快速变化，当前保存像素快照的维护成本高于回归价值。
- Bot playtest：暂不运行。玩法是两名真人、三角色同时输入，当前最重要的证据是五局真实同机试玩；自动对局脚本应在人工基线出现后编写。
- 生产预览/部署：未宣称发布就绪，本轮只验证了生产构建和开发服务器浏览器路径。
- 音频：当前为 Web Audio 程序化占位反馈，不是正式音频资产。

## 7. 本轮发现并修复的问题

1. 脚手架测试仍读取旧单人示例的 `player/score/complete`，已迁移到 `kid/guards/delivered/matchState`。
2. Playwright 初始配置尝试使用自带 Chromium/WebKit；已改为直接使用系统 Chrome，窄屏仅做 Chrome 设备尺寸模拟。
3. 手机尺寸上下文请求缺失 favicon 导致控制台 404，已改为内联 SVG favicon。
4. `kid` 原计划缺少拾取停留状态，已在 V4/V5、模拟层、HUD、世界反馈和规则测试中统一为 `Picking`。
5. 试玩发现进入交付区会自动送完全部苹果，已改为 `Right Shift` 每个按下沿主动送达一个，并保留同 tick 抓捕优先。
6. R 键提示动画覆盖了状态条的水平居中变换，已让动画帧保留 `translateX(-50%)` 并加入桌面/窄屏回归。
7. 原计时标签“本局”可能被理解为限时赛，已改为“用时”，并明确首版无超时和平局。

## 8. 下一阶段：五局真人同机试玩

启动：

```powershell
npm run dev
```

浏览器打开 `http://127.0.0.1:5188`，重点记录：

1. `400ms` 拾取停留是“可被利用的机会”还是“接近必抓”。
2. 一名玩家同时操控两个 guard 是否过载，常见键盘是否丢组合键。
3. 普通接触和飞扑各自是否有明确价值。
4. 交付区是否可通过双 guard 长时间守死，以及逐个主动送达是否提供合理的守卫抓捕窗口。
5. 六个苹果与逐个 `10%` 减速是否产生多拿/先送/快速丢果的真实选择。
6. 在没有硬性时限的前提下，一局是否自然稳定在约 `2~5` 分钟结束，双方能否解释失败原因。

五局记录完成前，不进入正式角色资产、复杂动画或网络联机。
