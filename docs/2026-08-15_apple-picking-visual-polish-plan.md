# Apple Picking 视觉精致化方案

日期：2026-08-15  
状态：阶段一、阶段二已批准执行；场景全面扩建、HUD 重构和正式音频资产等待本轮评审后决定。

## 1. 目标与范围

本轮不改核心玩法规则，目标是用低面数但有明确艺术设计的模型、状态动画和事件反馈，让玩家在实际游玩距离下感受到角色有重量、苹果有价值、动作有前因后果。

本轮执行范围：

- 阶段一：建立“暖色低多边形微缩果园 + 轻喜剧追逐”的风格标杆。
- 阶段二：完成 kid、守卫和苹果的主要连续状态与瞬时事件表现。
- 保留 `GameSimulation` 的确定性和碰撞规则；表现层只消费 snapshot 和 event。
- 不进行全场景扩建、HUD 全面重构、正式背景音乐或外部生成资产接入。

## 2. 游戏设计契约

### 玩家承诺

三名玩家在一个像桌面玩具般的果园里进行紧张但滑稽的追逐：kid 越贪心越笨重，守卫越急越容易互相撞晕。

### 目标感受

- 紧张：kid 的负载和守卫的飞扑不断制造风险。
- 滑稽：重载喘气、汗滴、背包晃动、守卫飞扑与撞晕具有喜剧节奏。
- 清楚：不依赖 HUD 文字也能读懂主要状态。
- 精致：动作包含预备、接触和恢复，不以持续发光或随机粒子代替形体与动作。

### 核心循环

kid 拾取并携带苹果前往送达点，同时守卫通过移动和飞扑制造抓捕压力；携带越多，收益越接近胜利但移动越慢，被抓会掉落苹果并推进守卫胜利条件。

### 关卡与镜头契约

- 保留当前固定俯视斜角镜头和矩形果园，不改变可通行区域、障碍碰撞或出生点。
- 角色朝向、背包、苹果负载和飞扑方向必须从当前镜头一眼可读。
- 表现不能遮挡苹果、守卫、送达点或下一条逃跑路线。
- 移动端优先保证状态清楚，较小的环境装饰和高频粒子可以降级。

### 本轮非目标

- 不增加新胜负规则、技能、地图、联网或 AI。
- 不以高面数、复杂骨骼或大量 2K/4K 纹理为目标。
- 不以 bloom、浓雾、屏幕抖动或常驻状态环作为主要精致感来源。

## 3. 当前基线与风险

当前桌面和移动端 active-play 画面均可正常渲染，无控制台错误。基线诊断：

| --- | ---: | ---: | ---: |
| Draw calls | 106 | 106 | 移动端尽量不超过 130，硬上限 150 |
| Triangles | 5,162 | 5,162 | 移动端控制在 100k 内 |
| Geometries | 47 | 47 | 控制在 120 内 |

## 4. 艺术方向

### 形状语言

- kid：柔软、圆润、略前倾，重点轮廓是头、肩膀和会变化的背包。
- 守卫：更宽、更稳定、更方；蓝守卫与绿守卫通过帽子、体型和配件区分，而不仅是颜色。
- 苹果：低多边形、顶部凹陷、略不对称，准备矮胖、偏心、拉长三种变体。
- 果篮：用木条、把手、内衬和可增长的苹果堆替换功能圆圈的占位感。

### 材质语言

- 场景以高粗糙度的土、木、布料为主。
- 苹果使用稍低粗糙度，但不做玻璃般高光。
- 发光只用于拾取目标、无敌或飞扑信号等短时状态。
- 通过明度、轮廓和运动同时区分威胁与奖励，避免只依赖红绿颜色。

### 动作语言

- 连续动作：呼吸、重心交换、步态、背包惯性、苹果晃动。
- 行为动作：拾取、飞扑、眩晕、恢复。
- 瞬时反馈：拾取 pop、掉落弧线、捕获冲击、送达飞入。
- 优先级：瞬时事件 > 行为状态 > 移动 > 待机叠加。

## 5. 状态表现矩阵

| 对象/状态 | 身体与道具 | VFX/辅助 | 降低动态效果 |
| --- | --- | --- | --- |
| kid 待机 | 胸腹呼吸、重心轻移、头和背包有时间差 | 无常驻粒子 | 保留静态姿态差异 |
| kid 空载移动 | 身体前倾、手脚交替、轻微 squash/stretch | 极少量脚下尘土 | 取消弹性，只保留倾斜 |
| 携带 1–2 | 背包略鼓、苹果轻摇 | 无汗滴 | 静态负载轮廓 |
| 携带 3–4 | 背包下坠、步幅变沉、转弯有惯性 | 移动时偶发汗滴 | 单颗静态汗滴提示 |
| 携带 5–6 | 明显前倾、深呼吸、背包接近撑开 | 移动时 2–4 颗汗滴 | 保留强姿态，取消连续粒子 |
| 拾取 | 下蹲/伸手，进度越高身体越靠近目标 | 收缩进度环 | 固定在明确拾取姿态 |
| 被抓/无敌 | 短促压扁后回弹，背包收缩 | 冲击环、尘土、轮廓脉冲 | 单次冲击环，无闪烁 |
| 守卫可飞扑 | 身体略压低，帽子或肩部进入准备姿态 | 状态环只作弱辅助 | 静态准备姿态 |
| 守卫飞扑 | 身体拉长、帽子滞后、脚离地感 | 短速度线/尘土 | 保留拉长姿态 |
| 守卫眩晕 | 歪倒、头/帽子摆动 | 叶片或星星旋转 | 固定歪倒和眩晕标记 |
| 守卫恢复 | 从侧倒逐步撑起，帽子落稳 | 弱尘土 | 插值到起身姿态 |
| 苹果地面 | 不持续高速旋转；叶片轻摇，有接触感 | 目标苹果才显示提示 | 静态三种轮廓 |
| 苹果携带 | 相对 kid 朝向堆入背包，随负载产生惯性 | 无 | 固定在背包槽位 |
| 苹果掉落 | 短弧线、落地 squash、叶片延迟 | 小尘土 | 直接落地但保留短压扁 |
| 苹果送达 | 从背包飞入果篮，篮内苹果堆增长 | 小型收束环 | 直接显示篮内新增苹果 |

汗滴只在重载且正在移动时出现，避免成为无意义常驻装饰。

## 6. 表现层结构

- `GameSimulation`：继续拥有规则、位置、状态、计时和确定性随机。
- Snapshot：允许增加纯只读的移动强度等表现信息，不改变规则判断。
- `ArenaView`：根据 snapshot 处理连续 pose，根据当前负载和状态组合角色姿态。
- Event VFX：由 `picked`、`dropped`、`captured`、`delivered`、`pounce`、`guards-stunned` 等事件触发一次性效果。
- VFX 使用共享几何体/材质和固定容量池；视觉随机必须来自确定性输入或固定索引。
- reduced-motion 模式禁用高频晃动、旋转、闪烁和连续汗滴，但保留状态轮廓。

## 7. 资产策略

### 本轮

- 角色：Three.js 分件低模，使用关节 group 形成程序化骨架。
- 苹果：共享低模几何体的三种确定性变体。
- 果篮和篮内苹果：程序化模型。
- VFX：共享低面数几何体与透明材质，池化管理。
- 碰撞继续使用现有圆/AABB，不与视觉网格绑定。

### 后续可选

当游戏需要结算近景、角色选择或宣传镜头时，再评估 GLB 骨骼角色和外部生成资产。当前凭据检查结果：

- `TRIPO_API_KEY=MISSING`
- `GEMINI_API_KEY=MISSING`
- `ELEVENLABS_API_KEY=MISSING`

因此本轮不生成外部 3D、2D 或正式音频资产。

## 9. 验收标准

- 不看 HUD 文字，玩家可以区分 kid 空载、中载、重载以及守卫飞扑/眩晕。
- 携带苹果始终相对角色朝向位于背包区域，不在世界固定方向漂浮。
- 事件反馈不改变碰撞、计时、速度和胜负规则。
- reduced-motion 模式仍能读懂全部关键状态。
- `npm run build`、`npm test`、`npm run verify:visual` 通过。
- 桌面和移动端 active-play、heavy-carry、picking、guard-stunned、delivery 场景有非空截图且无控制台错误。
- 移动端 draw calls 目标不超过 130，硬上限 150；若超过则优先合并/实例化重复物，而不是删除关键角色状态。

## 10. 评审决策点

完成阶段一、二后，根据 active-play 和状态截图决定：

1. 继续扩建整个果园场景。
2. 先重构移动端 HUD 和镜头构图。
3. 配置外部资产凭据，制作近景角色或正式音频。
4. 保持当前资产路线，仅继续增加少量状态细节。

本轮选择了第 1 项，并将范围限制为不改变碰撞的场景纵深扩建。

## 11. 本轮实施结果（2026-08-15）

阶段一与阶段二已经完成，规则层保持确定性，视觉层通过 snapshot 和事件消费状态：

- 场景：围栏、垄线、树干和树冠改为共享几何体与实例化；果树改成多团块低多边形轮廓。
- 角色：kid、蓝守卫、绿守卫改为可分件驱动的程序化低模，守卫拥有不同体型、帽子和面部轮廓。
- 道具：苹果增加顶部凹陷、不对称、果梗和叶片；送达点替换为木条、内衬、把手和可增长苹果堆组成的果篮。
- 连续状态：待机呼吸、移动步态、拾取下探、负重前倾和背包膨胀、满载移动滴汗、飞扑拉伸、眩晕倒地与恢复起身。
- 瞬时事件：拾取、掉落、捕获、送达、飞扑和守卫相撞使用固定容量 VFX 池；苹果掉落与送达有短弧线过渡。
- 可访问性：reduced-motion 关闭高频摆动和连续旋转，但保留负重姿态、单颗汗滴、状态环和眩晕标记。
- 测试支持：新增 `heavy-carry`、`guard-pounce`、`guard-stunned`、`delivery-progress`、`captured` 确定性场景；画布检查器在指定状态时会冻结模拟，避免短状态在截图前结束。

### 性能结果

| 场景 | Draw calls | 三角面 | Geometries | Textures |

| 改造前 active-play | 106 | 5,162 | 47 | 3 |

角色状态纵切片曾将 active-play draw call 从 106 降至 60；场景扩建重新投入 24–25 次调用后，当前 active-play 仍比原始基线低约 21%，最高状态是移动端硬上限 150 的约 57%。DPR 最高为 2，无新增纹理、后处理或阴影灯。

Measured evidence：desktop active-play 的 color entropy 为 3.68、edge density 为 0.254、luminance contrast 为 166.7、dominant color share 为 0.294；mobile 分别为 3.96、0.332、170.7、0.285。相较场景扩建前 desktop entropy 2.98 / dominant share 0.426，空间层次和色块分布明显增加。

### 当前建议

场景层次扩建已经完成。下一轮建议优先处理移动端 HUD 与镜头构图：压缩上方状态区的高度，减少世界上下的大块留白，并保证工具棚等侧边地标在窄屏中有意裁切。正式音频继续保持独立评审项，不与布局改造混在同一轮。

## 12. 交付账本

### Game design brief / Core loop / Level/encounter plan

- Game design brief：低多边形风格不追求写实面数，把预算集中在俯视轮廓、关键状态和即时反馈。
- Core loop：kid 拾取苹果并承担逐级减速与暴露风险，守卫通过移动、飞扑和捕获阻止送达；全部送达或累计三次捕获结束对局。
- Level/encounter plan：单屏围栏果园保持现有碰撞和路线，三块果树形成遮挡/绕行选择，右下果篮形成明确终点；下一阶段只增加非碰撞或使用简单代理的叙事道具。

### Skill-loading ledger

- `threejs-game-director`：统筹范围、阶段和交付审计。
- Gameplay systems：核对规则/表现分层、核心循环和 game feel；没有修改规则顺序。
- AAA graphics：用于低模形状语言、共享材质、实例化和技术美术预算；本轮不宣称 AAA 或最终品质。
- UI：评估了 HUD/世界构图关系，本轮未改 HUD，重排留到独立阶段。
- Debug/profile：用于基线、draw call、三角面、DPR 和错误检查。
- QA/release：用于桌面/窄屏、真实输入、确定性状态和画布像素验收；本轮不做发布声明。
- `threejs-3d-generator` / `threejs-image-generator` / `threejs-audio-generator`：仅用于资产路线与凭据可行性评估；因凭据缺失未生成外部资产。
